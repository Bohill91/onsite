TASK: Fix the Exact Entrance map loading/fallback delay based on the completed diagnosis.

This is a focused reliability/UX fix.

The diagnosis established:

- Normal standalone vector-map loading is healthy:
  approximately 0.3–1.4 seconds.
- Replit Preview sometimes fails the MapLibre/vector path.
- When that happens, the current code waits up to 12 seconds before creating the Leaflet raster fallback.
- During that wait the user sees only the pale map-container background.
- The iframe itself is not inherently slow.
- The problem is the slow failure/fallback path.

Do NOT redesign the map.
Do NOT change map styling.
Do NOT change viewport/framing logic.
Do NOT change entrance pin positioning.
Do NOT change confirmed/draft state behaviour.

==================================================
1. REDUCE THE FALLBACK WAIT
==================================================

Locate the existing vector initialization timeout, currently approximately:

pickerMapLoadTimeout = setTimeout(..., 12000)

The 12-second timeout is far too long.

Change the fallback threshold to approximately:

2000 ms

Use a named constant if appropriate rather than burying a magic value.

The purpose is:

- allow normal MapLibre initialization time
- but do not leave the user staring at a blank panel for many seconds

Do NOT reduce it so aggressively that normal cold vector loads fall back unnecessarily.

Target approximately 2 seconds.

==================================================
2. FALL BACK IMMEDIATELY ON FATAL VECTOR FAILURE
==================================================

Inspect the existing MapLibre initialization/error handling.

Currently MapLibre errors can be recorded without immediately rejecting the initialization promise, meaning the app may still wait for the entire timeout.

Improve this.

If initialization encounters a genuinely fatal condition such as:

- WebGL unavailable
- map/canvas cannot initialize
- style fails to load in a way that prevents rendering
- renderer cannot start

then reject the vector initialization immediately and create the existing raster fallback.

Do NOT fall back merely because one non-critical tile/font request emits a recoverable MapLibre warning.

Be conservative.

Only fatal initialization/rendering failures should cause immediate fallback.

==================================================
3. PRESERVE VECTOR AS THE PRIMARY MAP
==================================================

The normal OnSite vector map must remain the preferred renderer.

Do NOT make Leaflet/OpenStreetMap raster the default.

Expected sequence:

1. Open Exact Entrance
2. show loading state
3. attempt current MapLibre vector renderer
4. if successful, show existing polished vector map
5. if fatal failure OR ~2 second bounded timeout, switch to existing Leaflet raster fallback

Do not alter the visual style JSON.

==================================================
4. ADD A REAL LOADING STATE
==================================================

Currently the user sees an unexplained pale/beige rectangle while the renderer is starting.

Add a restrained loading state INSIDE the map container.

It should fit the existing OnSite design language.

Preferred appearance:

- same neutral map container
- small subtle loading indicator
- text such as:

"Loading map…"

Centered or appropriately positioned.

No giant spinner.
No skeleton map.
No orange full-screen loader.
No layout shift.

The map container must keep its existing dimensions while loading.

==================================================
5. REMOVE LOADER AT THE RIGHT TIME
==================================================

The loading state should disappear when either:

A) the vector map has produced its first usable render

OR

B) the raster fallback has produced its usable map

Do not remove the loader merely because the MapLibre constructor returned.

The user should not see:

loader → blank beige map → actual map

The transition should be:

loader → usable map

as cleanly as possible.

==================================================
6. FALLBACK TRANSITION
==================================================

When vector initialization fails:

- cleanly destroy any partial MapLibre instance
- remove its canvas/listeners
- initialize the existing Leaflet raster map
- preserve the same current center
- preserve the same zoom/framing logic
- preserve the same draft entrance pin coordinates
- preserve click-to-place
- preserve draggable marker
- preserve + / − controls
- preserve recenter behaviour
- preserve confirmation state

There must not be a flash of two maps or stacked canvases.

==================================================
7. DO NOT BREAK MANUAL PIN STATE
==================================================

This is important.

If the worker/company user has already moved the entrance pin, the fallback/retry path must NOT reset it to the geocoded address center.

Current pin coordinates remain authoritative.

Preserve the earlier fix for this.

==================================================

- park/water styling
- label styling
- orange pin appearance
- map height
- map border/radius
- control styling
- attribution styling
- opening zoom/framing algorithm
