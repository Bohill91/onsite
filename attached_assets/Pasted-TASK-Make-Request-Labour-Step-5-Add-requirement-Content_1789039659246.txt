TASK: Make Request Labour → Step 5 → Add requirement → Content visually consistent across all six requirement types.

This is a focused UI/UX consistency pass.

The underlying type-specific logic is broadly correct.

DO NOT make every requirement type contain the same fields.

Different requirement types genuinely require different information.

The goal is:

CONSISTENT DESIGN SYSTEM
+
TYPE-SPECIFIC CONTENT

Do not redesign the modal from scratch.

==================================================
CURRENT QUALITY ISSUE
==================================================

Review the Content step as ONE six-type flow.

The current individual screens are reasonably good, but they do not yet feel like they were designed as one coherent system.

Observed issues:

1. External Training has vertically misaligned paired inputs.
2. Document and Form & signature use very large upload blocks.
3. Document and Form upload treatments are not perfectly consistent with each other.
4. Video uses a very different visual source pattern.
5. Several screens contain large muted grey information/empty-state blocks while others do not.
6. Some source sections consume too much vertical space.
7. Modal height changes more than necessary between comparable complex requirement types.
8. Supporting/primary content actions use inconsistent visual weight.

Fix these issues without flattening legitimate type differences.

==================================================
2. CONSISTENT FIELD LABEL ALIGNMENT
==================================================

Fix External Training specifically.

Current problem:

Training provider
Optional

sits beside:

Training title *

Because "Optional" occupies a second line on the left, the two input boxes begin at different vertical positions.

This is not acceptable.

Change optional metadata in paired rows so it does NOT alter input alignment.

Preferred pattern:

Training provider  Optional

Training title *

with both labels occupying the same vertical label row.

Both input boxes must start at EXACTLY the same Y position.

Apply the same principle anywhere else inside the Add requirement modal where:

- one field is optional
- the adjacent field is required

Optional status must never push one input lower than its neighbour.

Do not globally redesign every application form in this task.

==================================================
3. CREATE ONE COMPACT PRIMARY-SOURCE PATTERN
==================================================

Document and Form & signature currently use oversized stacked source areas:

example:

No document uploaded.

[large full-width Upload document area]

and:

No PDF uploaded.

[large full-width Upload PDF area]

These occupy too much space.

Create one reusable compact primary-source component/pattern for file-based requirements.

It should look approximately like:

DOCUMENT
Upload the document workers need to review.

[ No document uploaded.                 Upload document ]

and for Form & signature:

SOURCE DOCUMENT
Upload the PDF workers will complete and sign.

[ No PDF uploaded.                           Upload PDF ]

The exact markup may follow the existing design system.

Important principles:

- one contained row rather than two large stacked blocks
- filename/status on the left
- clear action on the right
- approximately normal input/control height
- subtle neutral border
- no giant drop-zone appearance unless drag/drop genuinely exists
- action must obviously look clickable
- Document and Form must use the SAME component styling

After upload, the same component should show:

- filename
- replace/change action
- remove action if currently supported

Do not fake capabilities that do not exist.

6. VIDEO INDUCTION
==================================================

Video is legitimately different because its current primary source is a URL.

However, make the VIDEO SOURCE section visually belong to the same system.

Current screen contains too many vertically stacked pieces:

- No video source added
- Video URL
- security/helper grey strip
- Add content later
- Supporting materials
- No resources added
- Add resource

Simplify it.

Preferred structure:

Video URL *

[input]

Do NOT use a large grey information panel for this simple helper.

Therefore REMOVE the redundant:

"No video source added."

empty-state bar if it adds no additional value.
