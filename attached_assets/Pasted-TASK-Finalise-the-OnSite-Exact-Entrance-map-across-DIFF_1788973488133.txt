TASK: Finalise the OnSite Exact Entrance map across DIFFERENT TYPES OF LOCATION.

There are TWO remaining issues:

1. The vector-map visual hierarchy is still too washed-out across suburban,
   dense urban and mixed locations.
2. The automatic opening viewport is too dependent on a fixed zoom and behaves
   very differently depending on the physical size/density of the site.

Solve BOTH issues as one coherent final map pass.

IMPORTANT:

Do NOT optimise the map around Amazon DHA1 or any single test location.

Amazon, residential/suburban, Golders Green and central London examples are QA
cases only.

The final implementation must work generically across UK construction sites.

Do NOT:
- change map provider
- change renderer
- change fallback architecture
- change geocoder provider
- change pin interaction
- change confirmation logic
- change unrelated Step 4 UI
- edit demo/fixture/seed/sample data

==================================================
PART A — CROSS-LOCATION VISUAL HIERARCHY
==================================================

The current styling has the correct overall direction:

- clean
- neutral
- modern
- restrained
- orange OnSite pin
- no ugly yellow roads
- no pink/purple industrial land
- low POI clutter

KEEP THAT DIRECTION.

However, across multiple locations the map is still approximately 10–15% too
washed-out.

The user should be able to understand the physical layout immediately.

The visual hierarchy should clearly read:

1. ROAD NETWORK
2. BUILDINGS
3. GREEN / WATER
4. USEFUL LABELS
5. SECONDARY INFRASTRUCTURE / DETAILS

Do not make everything equally prominent.

==================================================
1. GENERAL LAND
==================================================

Keep general land:

- warm off-white
- light neutral
- visually quiet

Approximate family:

#F5F5F2

or the closest value appropriate to the current vector style.

Do NOT introduce:
- pink industrial land
- purple land
- strong beige fills

The land is the background.

==================================================
2. BUILDINGS
==================================================

Buildings currently merge too much with the land in several locations.

Increase building visibility enough that individual footprints are immediately
readable.

Target general family around:

#D4D6D3 – #D9DBD8

Use a restrained slightly darker outline where supported.

Buildings should be clearly darker than general land.

Do NOT make them:
- dark
- brown
- visually dominant

Acceptance:

At residential and dense-city locations, individual building blocks should be
easy to distinguish without zooming further.

==================================================
3. LOCAL / ACCESS ROADS
==================================================

Entrance access is one of the most important parts of this map.

Local roads should remain:

- white / near-white
- crisp
- visually separated from surrounding land

Strengthen the road casing/edge enough to make the network obvious.

Approximate visual family:

road fill:
#FFFFFF

road casing:
#CFD3D1 – #D5D8D6

Do NOT use yellow/orange road fills.

==================================================
4. ROAD HIERARCHY
==================================================

The current map does not distinguish road importance strongly enough.

Create a clearer hierarchy:

SMALL ACCESS / SERVICE ROAD
- crisp white
- subtle casing
- narrow

NORMAL STREET
- slightly wider / stronger casing

IMPORTANT LOCAL / SECONDARY ROAD
- clearly more prominent
- slightly stronger width / casing
- still neutral

MAJOR ROAD
- strongest neutral road treatment
- must still not dominate everything else

Do not create an Apple Maps clone.

Use Apple Maps only as inspiration for how easily the road hierarchy can be
understood at a glance.

==================================================
5. LABELS
==================================================

Road labels are currently too faint across several locations.

Increase useful road-label contrast by approximately 15–20%.

Target family:

#505A63 – #5C6670

Prioritise:

- road names
- access roads
- immediate site/building names where available
- useful transport/landmark references

Keep secondary labels lighter.

Do NOT increase miscellaneous POI clutter.

==================================================
6. POI CLUTTER
==================================================

For the Exact Entrance map, orientation matters more than business discovery.

Reduce prominence of:

- shops
- restaurants
- entertainment
- miscellaneous commercial POIs

where the current vector style supports it.

KEEP:

- roads
- building labels
- transport infrastructure
- useful immediate landmarks

Do not remove useful context blindly.

==================================================
7. GREEN + WATER
==================================================

The current colour direction here is good.

Keep approximately:

GREEN:
soft muted green such as #DCEBD7 family

WATER:
clear pale blue such as #BFE3EF family

Ensure they remain clearly distinguishable from general land.

Do not over-saturate.

==================================================
8. RAIL
==================================================

Rail should remain visible but subordinate.

Across industrial/urban examples it should NOT compete with:

- site access roads
- target building
- local streets

Reduce rail visual strength where necessary.

Keep it useful for orientation.

==================================================
9. ONSITE PIN
==================================================

KEEP the existing orange entrance marker.

It is now correct.

Do not redesign it.

No:
- number
- label
- pulse
- glow
- bounce

It should remain the strongest individual map element.

==================================================
PART B — ADAPTIVE OPENING VIEWPORT
==================================================

STOP trying to solve entrance-map framing with one magic zoom number.

Different sites require different framing.

Examples:

- a huge logistics warehouse
- a small suburban building
- a dense central-London building

cannot always open at exactly the same zoom and provide equivalent useful
context.

The desired result is:

TARGET SITE
+
IMMEDIATE ACCESS ROADS
+
NEAREST USEFUL JUNCTIONS
+
NEIGHBOURING BUILDINGS

NOT:

one giant building filling the map

and NOT:

a district-level overview.

==================================================
10. INSPECT GEOCODER RESULT DATA
==================================================

Inspect the current Site Address geocoder response/model.

Determine whether selected locations currently provide:

- bounding box / bbox
- feature bounds
- geometry
- feature type
- place type
- result precision
- address/building/street classification

Do not invent data that the geocoder does not provide.

Use the best trustworthy data already available.

==================================================
11. PREFERRED METHOD — FIT TRUSTWORTHY BOUNDS
==================================================

IF the selected geocoder result provides a trustworthy bounding box or feature
bounds:

prefer:

fitBounds(featureBounds, padding)

rather than immediately choosing one fixed zoom.

Add generous context padding around the feature.

The view should include more than the literal building bounds because the user
needs access-road context.

Use approximately:

50–90px effective map padding

depending on current provider/API behaviour.

After fitBounds:

CLAMP the resulting zoom.

Do not allow absurd extremes.

Suggested initial clamp:

MINIMUM / WIDEST:
approximately 16.0–16.3

MAXIMUM / CLOSEST:
approximately 17.2–17.4

Tune based on actual live results.

The important behaviour is the CLAMPED ADAPTIVE VIEW, not the exact numbers.

==================================================
12. LARGE FEATURE HANDLING
==================================================

A large warehouse/logistics site may have a much larger feature footprint.

If valid feature bounds exist:

fit the whole useful site/building context plus immediate access roads.

Do NOT zoom in until a large warehouse becomes a giant grey rectangle filling
the map.

At the same time:

do not zoom so far out that unrelated neighbourhood landmarks dominate.

==================================================
13. SMALL BUILDING / DENSE URBAN HANDLING
==================================================

For small buildings in dense areas:

the fitted feature itself may be tiny.

Clamp maximum zoom so the user still sees:

- building
- street
- neighbouring junction
- nearby immediate context

Do not zoom to an excessively close single-building view.

==================================================
14. FALLBACK WHEN NO BOUNDS EXIST
==================================================

If trustworthy bounds are NOT available:

use geocoder precision/type.

Create a small central helper for entrance-context zoom.

Example conceptual logic:

PRECISE BUILDING / ADDRESS
→ approximately 17.0

STREET / ROAD ADDRESS
→ approximately 16.6

LESS PRECISE LOCAL RESULT
→ approximately 16.2

Do not scatter these numbers through app.js.

Use one clear source of truth/helper.

==================================================
15. DO NOT USE ADDRESS TEXT GUESSING
==================================================

Do NOT infer site size based on:

- "Amazon"
- "warehouse"
- postcode formatting
- project name
- manually guessed keywords

Use actual geocoder geometry/precision where available.

==================================================
16. SAVED EXACT ENTRANCE
==================================================

When:

Edit entrance

is opened for an already confirmed exact pin:

centre on the SAVED ENTRANCE.

Use a useful close-context view.

If valid site bounds remain available, consider them when framing.

Otherwise use approximately:

16.8–17.2

depending on actual map scale.

Do not open on a featureless close-up.

17. RECENTRE CONTROL

Re-centre on site address should re-run the same generic entrance-context framing

bounds if trustworthy
otherwise precision-based fallback.

Do NOT use a completely separate fixed zoom for Re-centre.

Keep one shared viewport strategy.
